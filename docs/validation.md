# 自动运行引用错误修复验证

验证日期：2026-10-19。版本：0.4.1。

## 复现

从本地只读数据库取得最近失败的候选：正文 3335 字符，原审核含 8 条引用，其中 5 条不是原文子串。此前的流程会把审核引用错误交给作者重写，因而连续生成仍可能停在 0 章。

## 修复

- 审核选择程序提供的原文片段编号，程序按原始字符位置提取引用。
- 验收项以编号对应，名称和顺序由程序恢复，不再让模型复制条件文本。
- 审核结构错误在原稿上重审，最多额外两次；只有实质性内容矛盾进入作者修订循环。
- 审核异常或暂停后的候选可按创作指纹恢复；规划、设定或前文版本变化时禁止自动复用。
- 页面先读任务状态，再读作品，避免把「已完成任务」与旧章节快照组合后过早停止轮询。

## 真实模型验证

使用本机已经配置的 Responses 模型，在临时数据库副本中测试；实际书籍数据库没有被写入，创作正文与密钥没有提交到仓库。

1. 对失败的 3335 字符候选重新审核：一次调用通过，提取 6 条事实，没有重写原稿。
2. 在同一隔离副本上启动后台自动运行，要求新增 2 章：任务状态正常进入 `completed`，实际新增 2 章。
3. 目标作品在副本中最终保留 3 章、12407 字符，事实与阶段验收合计 25 条引用，25 条均存在于各自正文。

这是有限的真实端点回归验证，不能据此保证任意提供商或长篇文学质量。片段引用存在性由程序保证，事实的语义支持关系仍依赖模型审核。

## 自动化验证

- Python 3.10、3.12 各通过 56 项离线测试：覆盖真实原文偏移、长行与 Unicode、无效编号、同稿重审、修复上限、候选恢复、规划变化后禁用恢复，以及原有事务和运行流程。
- Chromium 浏览器烟测：三字段建书、手动推进、正文编辑、草稿和失败候选恢复、历史、阶段切换、后台自动运行、导出和手机布局。
- Ruff、格式检查和 Git 空白检查。
