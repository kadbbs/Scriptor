# 接口故障与后台恢复

## 503 不等于 Schema 不兼容

0.6.1 将连接错误、429、5xx 与认证、权限、路由和参数错误分开提示。503 表示服务暂不可用，仅凭它不能确认是模型、容量、路由还是中转内部故障。Anthropic 官方说明 SDK 会有限重试暂时故障，参见[接口错误文档](https://platform.claude.com/docs/en/api/errors)。

本次实际排查中，失败发生在新书构思阶段，尚未生成正文。对当前配置的中转地址和模型，发送仅要求返回简单文本或 JSON 的最小请求：

- 不带原生 Schema 的 Messages 请求：503。
- 带原生 Schema 的 Messages 请求：503。
- 流式 Messages 请求：503。
- 模型列表请求：200，且列出当前模型；这只能说明列表可访问，不能证明生成渠道可用。
- 后续探测也出现过连接失败；改用 Bearer 认证测试生成仍返回 503。

没有发送用户小说正文作连接测试，也没有切换模型、修改密钥或改写原书。这些证据将故障缩小到中转的生成链路，但不足以确认中转内部的具体原因。关闭结构化输出不是本次已验证有效的解决办法。需要在中转后台核对该模型的渠道、配额与上游状态，或等待服务恢复。

后续排查还发现了另一类项目兼容性问题：同一中转返回 200，却未遵守原生 Schema、输出 Markdown，导致真实构思解析失败。这与 503 应分别定位，修复及不同型号的对照见 [Anthropic 兼容性排查](anthropic-compatibility.md)。

## 自动运行的有限重试

```dotenv
SCRIPTOR_AUTO_RETRIES=2
SCRIPTOR_RETRY_DELAY=5
```

SDK 自身最多重试两次。后台在暂时故障最终抛出后，再最多重试当前推进步骤两次，默认等待 5、10 秒；数字 Retry-After 可以延长等待，每次最多 60 秒。`SCRIPTOR_AUTO_RETRIES=0` 关闭后台额外重试。配置范围分别为 0–5 次、0–60 秒。

等待时页面显示等待时长与重试次数，任务继续保持心跳。点击暂停会结束等待，不启动下一次模型请求。持续故障耗尽次数后仍会停止，不能通过不断重试修复失效的上游。

每次重试重新读取已完成的构思、规划和正文；同一创作指纹下已保留的候选通过原有恢复机制重新审核。不会把失败算成新增章节，也不会放宽事实或文学检查。401、403、404、400/422、模型输出格式错误和文学退稿不进入这一后台临时故障重试。

## 查看与恢复

1. 更新代码与依赖，重启服务；环境变量修改也需要重启。
2. 请求本机 `/health`，确认 `provider` 与 `api_format` 符合预期。
3. 查看「运行记录」中的失败步骤与调用诊断。新记录保留 HTTP 状态和合法的请求编号，不记录响应正文、认证头或密钥。失败时 token 用量可能未知。
4. 确认中转生成线路恢复后，再次开始自动运行即可从现有进度继续。

## 验证

Python 3.10、3.12 各通过 99 项离线测试；覆盖临时错误分类、永久错误不重试、重试等待上限、候选复用、持续故障有界停止、等待中暂停与原有完整流程。Chromium 烟测通过。测试隔离本机 `.env` 和提供商环境变量，避免意外读取真实凭据。

真实端点的最小探测复现了 503 与连接故障；没有声称上游已经恢复或真实连写已成功。
